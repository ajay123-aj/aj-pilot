Auto deploy

Merge or push — it deploys itself

Pick the branch an app runs — main, master, dev or any other — and choose what deploys it. The panel rebuilds and restarts the app on its own, and shows you exactly which change went live.

  • Every push or commit — any new commit on the branch goes live, ideal for a staging or dev server.
  • Only merged pull / merge requests — a reviewed dev → main merge deploys production; direct pushes are left alone.
  • Instant with a webhook on GitHub, GitLab or Bitbucket, added for you — or the branch is checked every minute, even behind a firewall.
  • Live progress and full history — step by step with the live log, and every deploy kept with its branch, merge or commit, time and author.

Environments

Every variable, kept once

Keep database URLs, API keys and secrets as named environments — shop-production, shop-staging — and use them for any app or service instead of pasting .env files around.

  • Import a .env file when you add or edit one — comments and quoted values are read as they are.
  • Pick one when you create an app, a one-click database or a systemd service — its values fill the form.
  • Or save as you go — name a new environment while creating an app or service, and it is there next time.
  • Encrypted, and safe to share — values are AES-256 encrypted; view-only teammates see the names, never the secrets.

About AJ Pilot

Our story

AJ Pilot started as a way to stop keeping a dozen SSH sessions open just to answer simple questions: what is running on that box, is the disk filling up, which port is that, did the app come back after the reboot.

It grew into a complete control panel: servers, apps, domains, databases and teams, all in one place. It is a single Node.js process with a MySQL database and a plain browser UI — and everything it does, it does over the same SSH connection you would have used by hand, telling you exactly what it ran when something fails.
