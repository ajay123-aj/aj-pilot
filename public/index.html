Everything you need to run production servers

How it works

Bare server to live app in four steps

From a fresh Ubuntu server to an app running on your own domain, without opening a terminal.

  1. 1

    Add a server

    Host, SSH user and a password or key. The connection is tested before it is saved, and the panel says exactly what went wrong if it cannot get in.

  2. 2

    Install what it needs

    Docker, Nginx and any database or cache, with one click each. Everything runs in containers with its data kept safe in volumes.

  3. 3

    Deploy your app

    Pick a repository, branch and folder. Watch it build and start step by step, with the full log.

  4. 4

    Put it on your domain

    Choose a Cloudflare domain and a subdomain. DNS, Nginx and SSL — or a Zero Trust tunnel — are set up for you.

Security

Built to be trusted with root

It holds the keys to your servers, so it is careful with every one of them.

  • Your infrastructure only. The panel talks straight to your servers over SSH. No agents, no vendor in the middle, no telemetry.
  • Encrypted at rest. Every credential is AES-256-GCM encrypted with a master key that stays on your disk.
  • Roles enforced server-side. The API checks permission on every change, whatever the browser sends.
  • Sessions you can end. HttpOnly cookies with random tokens stored only as hashes; a new role or password signs that person out everywhere.
  • Careful with destructive work. Removing an installation keeps its data volume unless you say otherwise.
  • Nothing typed into a shell. Names, ports and units are validated against strict patterns before anything runs.

About

About AJ Pilot

AJ Pilot started as a way to stop keeping a dozen SSH sessions open just to answer simple questions: what is running on that box, is the disk filling up, which port is that, did the app come back after the reboot.

It grew into a complete control panel: servers, apps, domains, databases and teams, all in one place. It is a single Node.js process with a MySQL database and a plain browser UI — and everything it does, it does over the same SSH connection you would have used by hand, telling you exactly what it ran when something fails.
